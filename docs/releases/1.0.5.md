# Laundry Monitor Card 1.0.5

First stable-version release of the separately maintained Lovelace card, prepared
for the Laundry Monitor integration **0.1.8-rc8 and later**.

## Changes

- **Live cycle duration:** configure the new `cycle_started_at_entity` field
  using the integration's timestamp sensor (for example
  `sensor.washing_machine_cycle_started_at`). During `running` and
  `final_spin`, the card computes elapsed time locally from the sensor
  timestamp and the browser clock. The visible timer refreshes once a second
  without posting Home Assistant state updates or creating Recorder history.
- **Lifecycle-safe updates:** one browser timer while active; no timer after
  completion, card disconnection or configuration changes.
- **Compatibility:** existing `current_cycle_duration_entity` remains usable
  as a *static snapshot* if the new timestamp is not configured or is invalid.
  For active cycles, an old last-cycle duration is never substituted as though
  it were the current cycle. Once the cycle ends, the card displays
  `last_cycle_duration`.
- **Optional heating diagnostics:** visual editor now offers
  `heating_state_entity` and `heating_active_entity` in a Heating group.
- **Documentation and tests:** updated English/Russian README and sample YAML,
  with 10 Node regression tests covering timezone offsets (including +03:00),
  state transitions, legacy configurations and timer lifecycle.

## Compatibility and upgrade notes

The new timer is **opt-in at the card configuration level**. Existing Lovelace
YAML continues to load unchanged, but it does not automatically know the ID
of the new timestamp entity: open the visual editor and select *Cycle started
at (live timer, recommended)*, or set `cycle_started_at_entity` explicitly.

Example:

```yaml
type: custom:laundry-monitor-card
cycle_state_entity: sensor.washing_machine_cycle_state
cycle_started_at_entity: sensor.washing_machine_cycle_started_at
last_cycle_duration_entity: sensor.washing_machine_last_cycle_duration
```

The `hacs.json` metadata still declares Home Assistant **2024.11.0** as the
frontend minimum; this historical lower bound was **not independently
regression-tested for this release**. The paired integration 0.1.8-rc8
requires Home Assistant Core **2026.6.0+**. Confirm your actual entity IDs in
Home Assistant.

**HACS release channel:** Earlier card `1.0.4-rc3` was published with
`prerelease=false` and was effectively a regular/Latest release despite
its RC suffix. Version `1.0.5` is an intentionally stable, regular GitHub
Release (`prerelease=false`), so default-channel HACS users should be able to
see it as an update after refresh. No edits to old tags or release metadata
are necessary. The repository is not listed in the default HACS catalog;
it can be installed as a custom repository.

## Validation and publication

- Automated PR checks: JavaScript syntax, custom-element smoke load, ten
  Node regression tests, formatting and HACS validation.
- Manual display smoke test in Home Assistant remains required before
  publication: running/FINAL_SPIN ticking, finished duration, editor field
  selection, detach/reconnect and browser refresh. Do not treat automated
  success as proof of browser UI behavior.
- Publish from the verified post-merge `main` commit as tag **`1.0.5`**,
  choose a normal GitHub Release (**not** Pre-release), and verify HACS
  installation and update. Do not reuse historical tags.
