# Laundry Monitor Card 1.0.6

Стабильный технический релиз отдельной Lovelace-карточки после
[1.0.5](https://github.com/undel-gh/Laundry-Monitor-Card/releases/tag/1.0.5).
Он предназначен для работы со стабильной
[интеграцией Laundry Monitor 0.1.8](https://github.com/undel-gh/HA-Laundry-Monitor/releases/tag/0.1.8)
(а также с аналогичной семантикой состояний, появившейся в 0.1.8-rc8).

Обновление исправляет отображение **текущей фазы**, когда детектор
финального отжима сохраняет исторический признак после завершения
стирки. Карточка **не** изменяет интеграцию, её сущности или историю.

## Изменения

### Индикаторы текущей фазы (issue #2, PR #3)

- Индикаторы **Стирка**, **Финальный отжим** и **Завершено**
  теперь показывают **текущую фазу цикла**, а не исторические
  признаки детекции. Если `cycle_state_entity` сообщает одно
  из распознаваемых состояний `idle`, `armed`, `running`,
  `final_spin`, `finished`, `error`, оно имеет приоритет
  перед противоречащими бинарными сенсорами.
- **Финальный отжим** активен только в состоянии
  `final_spin`. После перехода в `finished` и `idle`
  он выключается, даже если интеграция намеренно сохраняет
  `binary_sensor.<device>_final_spin_detected=on`.
  Состояние сенсора в HA карточка **не** меняет; нажатие
  по-прежнему открывает его стандартное окно `more-info`.
- Для старых **конфигураций только с бинарными сенсорами** и
  при недоступном/неизвестном состоянии цикла отжим активен
  только при одновременном `running_entity=on`,
  `final_spin_entity=on` и отсутствии
  `finished_entity=on`. Если `finished_entity=on`,
  **завершение имеет приоритет** перед противоречивым
  `running_entity=on`.
- **Живой таймер использует ту же логику фазы.**
  Исторический флаг отжима не продолжает отсчёт после
  окончания программы. Для завершённого цикла показывается
  `last_cycle_duration`.

### Обслуживание CI (PR #4)

- GitHub Actions `checkout` и `setup-node` обновлены до
  **v6**; проверки выполняются на **Node.js 24**, поэтому
  прежнее предупреждение об устаревании Node.js 20 устранено.
- Сохранены проверки синтаксиса JavaScript, smoke-загрузка
  Custom Element, полный набор Node-тестов, контроль пробелов
  в конце строк и HACS Validation. Карточке не требуются
  зависимости npm или lock-файл.
- Эти изменения относятся только к CI и не влияют
  на работу карточки в браузере.

[PR #4](https://github.com/undel-gh/Laundry-Monitor-Card/pull/4)

### Документация и регрессионное покрытие

- Описания приоритета фаз, поведения при отсутствии
  `cycle_state_entity` и живой длительности согласованы
  в английском и русском README.
- Набор тестов включает известные состояния, противоречивые
  бинарные флаги, недоступное состояние цикла, сохранённый
  признак финального отжима, старые конфигурации и жизненный
  цикл браузерного таймера. Последний CI объединённой ветки
  содержал **33 успешных Node-теста**.

## Совместимость и обновление

- **Нет миграции конфигурации, переименований YAML-полей
  или новых обязательных сущностей.** Старые карточки
  продолжают работать.
- Для рекомендуемого живого счётчика выберите
  `cycle_started_at_entity` — timestamp-сенсор интеграции.
  Это по-прежнему необязательная настройка карточки.
  `current_cycle_duration_entity` в интеграции 0.1.8 —
  **снимок на значимых переходах**, а не непрерывный таймер.
  После окончания используется `last_cycle_duration_entity`.
- **Карточка и интеграция выпускаются независимо.**
  Для интеграции Laundry Monitor **0.1.8 stable** необходим
  Home Assistant Core **2026.6.0+**. В `hacs.json` карточки
  по-прежнему указан исторический минимум фронтенда
  **2024.11.0**; эта старая версия **не проходила отдельную
  проверку совместимости** для данного релиза.
- Репозиторий пока доступен через **Custom repositories в HACS**,
  а не в глобальном каталоге. Версию `1.0.6` необходимо
  публиковать как **обычный стабильный GitHub Release**
  (`prerelease=false`). После обновления каталога она
  станет доступна пользователям стабильного канала.
- Если браузер продолжает использовать старый JavaScript,
  обновите страницу/ресурс и проверьте сообщение
  **Laundry Monitor Card 1.0.6** в консоли браузера.

## Проверки

- До подготовки релиза в `main` уже объединены PR #3
  (текущие фазы) и PR #4 (CI). Соответствующий
  [HACS Validation run](https://github.com/undel-gh/Laundry-Monitor-Card/actions/runs/43779721544)
  завершился успешно. PR с изменением поведения подтвердил
  **33/33 Node-теста**.
- **Для выпуска 1.0.6:** необходимы зелёные задания
  `syntax` и `hacs` на **актуальном HEAD release PR**,
  а затем — на **итоговом коммите `main` после merge**.
  Зафиксируйте ссылки на реальные проверки.
- **Ручной smoke-тест интерфейса HA пока не объявляется
  выполненным.** Перед публикацией проверьте индикаторы
  `running`, `final_spin`, `finished`, `idle`,
  сохранённый исторический сенсор, binary-only fallback
  (если используется), остановку живого таймера,
  визуальный редактор/YAML, обновление страницы и
  отсоединение/повторное подключение карточки.
  Node-тесты не заменяют проверки в браузере.

## Известные ограничения и откат

- Карточка отображает вычисленную интеграцией фазу;
  не определяет самостоятельно вращение барабана и не
  гарантирует точную секунду физического отжима.
- При отсутствии распознаваемого `cycle_state_entity`
  используется осторожный fallback на бинарные сущности.
  Ненастроенные индикаторы скрываются: карточка не
  придумывает состояния и не изменяет сущности HA.
- При проблемах можно выбрать предыдущую исправную
  версию карточки (например, `1.0.5`) в HACS,
  если она доступна в выбранном канале, либо восстановить
  прежний JS-файл и обновить страницу браузера.

**Порядок публикации:** сначала проверить и объединить release PR,
дождаться CI на **итоговом коммите `main`**, затем создать на этом
коммите тег **`1.0.6`** и опубликовать обычный GitHub Release
с выключенным **Pre-release**. Подготовка PR сама по себе
не публикует релиз.
