# Laundry Monitor Card 1.0.6

Stable maintenance release of the separately maintained Lovelace card,
following [1.0.5](https://github.com/undel-gh/Laundry-Monitor-Card/releases/tag/1.0.5).
It is designed to work with the stable
[Laundry Monitor integration 0.1.8](https://github.com/undel-gh/HA-Laundry-Monitor/releases/tag/0.1.8)
(and with the equivalent cycle-state semantics introduced in 0.1.8-rc8).

This update corrects the **displayed phase** when final-spin detection is
latched across cycles. It does **not** modify the Laundry Monitor
integration, reset its entities or change their stored history.

## Changes

### Current-phase status chips (fix #2, PR #3)

- The **Running**, **Final spin**, and **Finished** chips now represent
  the **current cycle phase**, not historical evidence.
  When `cycle_state_entity` has one of the recognized values
  `idle`, `armed`, `running`, `final_spin`, `finished` or
  `error`, that state takes precedence over contradictory binary
  sensor values.
- The **Final spin** chip is active only in the
  `final_spin` phase. It is off in `finished` and `idle`, even
  when the integration intentionally retains
  `binary_sensor.<device>_final_spin_detected=on`.
  The card does **not** change that sensor's actual HA state or its
  normal `more-info` click target.
- For older **binary-only configurations** or unavailable/unknown
  cycle-state entities, Final spin is shown only if
  `running_entity=on`, `final_spin_entity=on`, and
  `finished_entity` is not `on`. An explicit
  `finished_entity=on` wins over a contradictory
  `running_entity=on`.
- The **live-duration display uses the same phase decision**.
  A stale historical final-spin flag does not keep the timer
  running after a completed cycle. The completed cycle continues
  to show `last_cycle_duration`.

### CI maintenance (PR #4)

- GitHub Actions `checkout` and `setup-node` upgraded to **v6**;
  CI uses **Node.js 24**, avoiding the previous Node.js 20
  deprecation notice.
- JavaScript syntax checking, custom-element smoke load, the full
  Node test suite, trailing-whitespace check and HACS validation
  remain in place. The source-only card still has no npm dependency
  installation or lockfile requirement.
- This change affects CI only, not browser/card behavior.

## Compatibility and upgrade notes

- **No configuration migration, YAML key rename or new required
  entity.** Existing cards remain valid.
- For the recommended browser-local live elapsed timer, configure
  `cycle_started_at_entity` to the integration's timestamp sensor.
  This configuration is still opt-in. The legacy
  `current_cycle_duration_entity` is only a transition-time
  snapshot on integration 0.1.8, not a live timer; after completion,
  use `last_cycle_duration_entity`.
- **The source integration and card are released separately.**
  For Laundry Monitor integration **0.1.8 stable**, Home Assistant
  Core **2026.6.0+** is required. The card's `hacs.json` still
  declares historical frontend minimum **2024.11.0**;
  compatibility at that older version has **not** been independently
  tested for this release.
- The repository is distributed as a **custom HACS Dashboard/plugin
  repository**, not yet as a default-catalog entry. Version
  `1.0.6` must be a **regular stable GitHub Release**
  (`prerelease=false`) so custom-repository users on the
  stable channel can update. Normal HACS refresh delays apply.
- If the browser continues to serve the old JavaScript resource,
  refresh/reload the dashboard, checking that the browser console
  reports **Laundry Monitor Card 1.0.6**.

## Known limitations and rollback

- The card displays the integration's inferred cycle phase;
  it does not independently detect drum rotation or guarantee
  an exact physical final-spin timestamp.
- A stale or missing `cycle_state_entity` causes conservative
  binary fallback. If essential sources are not configured,
  the relevant chips remain hidden; the card does not invent
  states or alter HA entities.
- For problems after upgrading, select the last known-good
  card release (for example `1.0.5`) through HACS where
  available or restore the previous JS resource, then refresh
  the browser.

**Publication procedure:** Review and merge the release-preparation

GitHub Release with these notes. Publishing is a separate action;
