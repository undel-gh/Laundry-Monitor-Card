# Laundry Monitor Card 1.0.5

Первая версия отдельно сопровождаемой Lovelace-карточки со статусом
**стабильного релиза**, подготовленная для интеграции Laundry Monitor
**0.1.8-rc8 и новее**.

## Изменения

- **Живой счётчик длительности:** новая настройка
  `cycle_started_at_entity` связывается с timestamp-датчиком интеграции
  (например, `sensor.stiralka_cycle_started_at`). В состояниях
  `running` и `final_spin` карточка вычисляет длительность локально по
  времени начала цикла и часам браузера. Отображение обновляется каждую
  секунду без публикации состояний в Home Assistant и записей в Recorder.
- **Безопасный жизненный цикл:** только один браузерный таймер во время
  активного цикла; после завершения, удаления карточки или смены настроек
  таймер останавливается.
- **Совместимость:** прежняя настройка `current_cycle_duration_entity`
  остаётся доступной как *статический снимок*, если timestamp не настроен
  или недоступен. Во время новой стирки длительность предыдущего цикла
  не выдаётся за текущую. После завершения отображается
  `last_cycle_duration`.
- **Диагностика нагрева:** в визуальном редакторе добавлены необязательные
  `heating_state_entity` и `heating_active_entity` в группе «Нагрев».
- **Документация и тесты:** обновлены EN/RU README и YAML-пример,
  добавлены 10 регрессионных Node-тестов, включая смещение +03:00,
  переходы состояний, старые настройки и остановку таймера.

## Совместимость и обновление

Для живого таймера **необходимо отдельно выбрать сущность** в настройках
карточки. Старый YAML остаётся рабочим, но новый timestamp-датчик
автоматически не определяется: в редакторе выберите поле
«Начало цикла (живой таймер, рекомендуется)» либо задайте
`cycle_started_at_entity` вручную.

Пример:

```yaml
type: custom:laundry-monitor-card
cycle_state_entity: sensor.stiralka_cycle_state
cycle_started_at_entity: sensor.stiralka_cycle_started_at
last_cycle_duration_entity: sensor.stiralka_last_cycle_duration
```

В `hacs.json` по-прежнему указан минимум для фронтенда
**Home Assistant 2024.11.0**; совместимость с этой старой версией
**не проверялась отдельно**. Интеграции Laundry Monitor 0.1.8-rc8
требуется Home Assistant Core **2026.6.0+**.
Используйте фактические идентификаторы сущностей из своего HA.

**Канал обновлений HACS:** ранее версия карточки `1.0.4-rc3`
была опубликована с `prerelease=false` и фактически считалась
обычным/Latest-релизом несмотря на суффикс RC.
Версия `1.0.5` выпускается как обычный стабильный GitHub Release
(`prerelease=false`), поэтому пользователи стандартного канала HACS
смогут получить обновление после обновления каталога.
Изменять старые теги и метаданные не нужно. Репозиторий отсутствует
в основном каталоге HACS, но доступен как пользовательский репозиторий.

## Проверки и публикация

- CI: проверка синтаксиса JS, smoke-load, 10 Node-регрессионных тестов,
  проверка форматирования и HACS.
- Перед публикацией необходимо вручную проверить карточку в Home Assistant:
  живую длительность при RUNNING/FINAL_SPIN, завершённую длительность,
  выбор сущности в редакторе, отключение/повторное подключение карточки
  и перезагрузку браузера. Успех CI не означает, что UI уже проверен.
- Создавайте тег **`1.0.5`** на прошедшем CI коммите `main`
  после squash-merge и публикуйте **обычный** GitHub Release
  (без Pre-release). Старые теги не переиспользуйте.

До создания GitHub Release этот документ — **черновик публикации**.
